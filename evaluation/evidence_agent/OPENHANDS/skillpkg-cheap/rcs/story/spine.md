# Paper Spine

1. **Problem.** Building agents that act on real software interfaces (writing and running code, using a terminal, browsing the web) requires environment, tool, and evaluation infrastructure that most research groups end up re-implementing per project, and evaluating one agent across many benchmarks is expensive {C011,C020}.
2. **Gap.** OpenHands' own evidence documents many separate agent systems, each with its own harness for a narrow task family (e.g., a SWE-Bench-only harness, a WebArena-only harness) {C001}, but no single open platform in this evidence package integrates a common agent abstraction with many benchmarks so that one agent can be evaluated across domains under one framework {C011}.
3. **Question.** Can one open, MIT-licensed platform, exposing a small common action interface, host a single generalist agent that is evaluated - without per-domain prompt changes - across software-engineering, web-browsing, and miscellaneous-assistance tasks, and does that agent reach measurable, reportable performance in each domain {C006}?
4. **Approach.** The authors built OpenHands around a small agent-action abstraction (three core actions: running code, running shell commands, and browser interaction) {C001}, a containerized, reproducibly-tagged runtime {C018}, deterministic integration tests that mock LLM calls {C019}, and harnesses for 15 established benchmarks {C011}; they then ran one generalist agent, CodeActAgent (and a BrowsingAgent variant for the web-browsing benchmarks), unmodified across these benchmarks {C006}.
5. **Key finding.** The same unmodified agent produces measured results in every domain: 26.0% resolve rate on SWE-Bench Lite with claude-3.5-sonnet {C002}, 79.3% pass rate on the HumanEvalFix Python subset with 0-shot self-debugging {C004}, 8.5-15.5% success on the 812-instance WebArena benchmark depending on the backend model {C007}, and 52.0% accuracy on the 198-question GPQA diamond set against an 81.3% expert-human reference {C008}.
6. **Meaning.** These results are consistent with a shared, minimal agent interface and a single generalist agent being sufficient to obtain interpretable, cross-domain performance numbers, rather than requiring bespoke agents and harnesses per benchmark family {C006}; however, the size of the effect depends heavily on which large language model backs the agent {C003}.
7. **Main limit.** Performance swings by roughly 4x between backend models on the same benchmark (26.0% vs. 6.3% on SWE-Bench Lite) {L001}; most reported numbers come from reduced-size, cost-driven benchmark subsets rather than full benchmarks {L002}; and the agents still struggle with complex tasks and editing long files {L003}, so the platform's generality claim is about infrastructure and measurement, not about solved agentic capability.
