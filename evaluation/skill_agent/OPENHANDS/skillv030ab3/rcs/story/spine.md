# Paper Spine (OpenHands)

1. **Problem.** Agents that act through software (code, a shell, a browser) are hard to build and evaluate, and each new agent tends to need its own environment, tools and benchmark harness. {C001} {C002}
2. **Gap.** As the authors describe existing frameworks, general ones offer limited or stateless code execution and software-engineering systems target GitHub issue fixing, so no single open platform is described that combines a sandboxed shell, Python and browser runtime, a shared tool library, agent delegation and a broad benchmark harness. {C004} {C005} {C006}
3. **Question.** Can one open platform host community-built agents that act through code, shell and browser (design question), and how does a default generalist agent built on it fare across software, web and assistance benchmarks without benchmark-specific prompt engineering (evaluation question)? {C003} {C026}
4. **Approach.** OpenHands: an event-stream architecture, a per-session Docker runtime with bash, IPython and Chromium, an AgentSkills library, agent delegation, an AgentHub of agents, and a harness integrating 15 benchmarks. {C010} {C011} {C015} {C017} {C019} {C024}
5. **Key finding.** The default CodeAct agent, unmodified, scored 26.0% on SWE-bench Lite (claude-3-5-sonnet), 79.3% on HumanEvalFix (gpt-4o) and 52.0% on GPQA diamond (claude-3-5-sonnet), and the OpenHands browsing agent scored 15.5% on WebArena; the authors call this competitive across three categories, while several references score higher. {C030} {C032} {C034} {C038} {C041} {C042}
6. **Meaning.** The platform makes agents and benchmarks comparable in one place, and the reported numbers place its generalist agents near, not consistently at, the top of the reference systems the authors list. {C024} {C042}
7. **Main limit.** By the authors' own account current agents still struggle with complex tasks and may not reach top performance in every category; the reported numbers come without variance or matched baselines. {L001} {L006} {L010} {L011}
