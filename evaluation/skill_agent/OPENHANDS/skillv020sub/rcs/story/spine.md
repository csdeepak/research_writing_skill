# Paper Spine

1. Problem. Researchers who want to build AI agents that act on the world through real software -- writing code, running a shell, browsing the web -- must currently assemble the pieces (an interaction interface, a safe execution environment, a tool library, multi-agent support, and evaluation) from separate, incompatible frameworks {C021}.
2. Gap. Existing open agent frameworks each cover only part of this: general orchestration frameworks give basic runtime support without a full sandbox {C021}; browsing- or prompt-optimization-specific frameworks cover one capability well but not the others {C021}; software-engineering-specialist agents fix GitHub issues well but do not generalize beyond that domain {C021}.
3. Question. Can one open platform supply all of these pieces together, and, once built, can a single generalist agent running on it -- with no per-benchmark modification -- perform competitively across qualitatively different task categories (software engineering, web browsing, and other tool-use/reasoning assistance) {C013}?
4. Approach. OpenHands answers this with an event-stream architecture connecting one agent to a Docker-sandboxed runtime (bash, Python, and a browser) through three core actions {C032}{C033}, an extensible AgentSkills tool library bounded by an explicit inclusion rule {C034}, multi-agent delegation, and an integrated evaluation harness spanning 15 benchmarks in three categories {C036}.
5. Key finding. The same CodeActAgent, run with no change to its system prompt, reached a 26.0% resolve rate on SWE-Bench Lite {C001}, 79.3% on HumanEvalFix {C003}, 52.0% on GPQA {C008}, and 32.1% on GAIA {C007} -- in the same range as, or above, category-specialist and prior domain-general baselines on most of the 15 benchmarks tested {C013}.
6. Meaning. Because the only thing held constant across categories is the interaction interface and runtime, not per-task engineering, the result suggests that a sufficiently general action space (code execution across bash, Python, and a browser) plus a shared runtime goes a long way toward generality, and that most of the remaining gap to specialists tracks the backbone LLM's own capability rather than the task category {C014}.
7. Main limit. The comparisons are not a controlled ablation -- baselines differ in backbone model, shot count, and training regime {L006} -- and the pattern is not universal: on MiniWoB++ a trained specialist system clearly outperforms every prompted agent shown, OpenHands included {L008}, and the authors themselves note that current agents still struggle with complex tasks {L002}.
