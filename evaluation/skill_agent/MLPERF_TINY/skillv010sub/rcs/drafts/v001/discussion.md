## 6. Discussion

The first submission round is consistent with a single suite letting markedly different submitters -- from a general-purpose microcontroller vendor to a team repurposing particle-physics tooling for an FPGA -- each show a distinct advantage under one shared, comparable protocol {C006}. That result is exactly the property the closed/open division split and the modular reference-implementation design were built to produce.

This is consistent with closing the gap described in Related Work by combining what no single prior effort combined: real ML workloads, MCU-class hardware, and energy measurement, delivered through a submission-and-review process similar to the one MLPerf's broader inference benchmark already uses (Reddi et al., 2019) {C012}. Where CoreMark measured the wrong workload, and MLMark and MLPerf Inference measured a closer workload on the wrong scale of hardware, MLPerf Tiny's reference models -- all under 350 kilobytes -- sit squarely inside the scale those two efforts do not reach {C012}.

There is early evidence that the suite is being put to use beyond this paper: MLPerf Tiny's benchmarks have already been used as a standard set of tasks in TinyML research, for instance in work on neural-architecture search for microcontrollers (Banbury et al., 2021) {C013}.

The same properties that make TinyML attractive carry a corresponding risk. Keeping data on the device that captures it, rather than transmitting it elsewhere, can widen access to machine learning and protect privacy; the same always-on, inexpensive sensing could equally be turned toward monitoring people without their consent, and the proliferation of cheap, single-purpose devices adds to electronic waste. A benchmark suite does not resolve these tensions, but a shared, community-developed one at least gives the field a common basis for discussing them.

### Limitations

Several limitations bound how far the round's diversity can be read. First, the evidence covers one round with five submissions and no parallel run of a non-modular alternative suite, so whether the diversity reflects the design specifically, rather than simply strong initial interest in a new community benchmark, cannot be separated with this evidence alone {L001}. Second, the reference accuracy and AUC figures behind each quality target's margin are each a single measurement; the paper does not report how much they would move under retraining, so the margin's robustness is untested {L002}. Relatedly, the specific latency and energy values the reference implementations achieved on their reference board are presented in the source material only as a figure, and could not be recovered as numbers for this account, so this paper can describe how latency and energy were measured but not what the reference implementations actually scored {L006}. Third, the closed division's four reference architectures are built mainly from fully-connected and convolutional layers; other families, such as recurrent networks, are reachable today only through the more flexible, less comparable open division {L005}.

A fourth limitation is a design tension the authors identify in their own suite, rather than one this analysis infers. Two of the four benchmarks, keyword spotting and anomaly detection, are naturally streaming tasks, but the measurement framework's host-to-device bandwidth makes a true streaming scenario difficult to reproduce without adding transfer delay. The suite instead excludes feature extraction from the measured window in the closed division, but doing so risks a degenerate case in which a submitter could define nearly the entire model as "feature extraction" to place it outside the measured portion. Including feature extraction instead would run into the opposite problem: in this non-streaming protocol, one second of audio implies roughly forty feature-extraction cycles for every inference cycle, over-counting the true cost of feature extraction {L004}. Neither choice is fully satisfactory, and the suite currently accepts the exclusion.

### Future directions

The authors describe three directions for closing these gaps. One is extending the suite to new application domains such as wearables, medical devices, and environmental monitoring, while keeping a stable long-term core subset so historical progress remains trackable {C014}. A second is widening the measurement scope to cover pre-processing and streaming behavior directly {C015}. A third is extending the closed division's architecture coverage beyond fully-connected and convolutional layers {C016}.
