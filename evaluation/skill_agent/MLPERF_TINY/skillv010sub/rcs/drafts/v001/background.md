## 2. Background: The TinyML Setting

Before turning to related benchmarks, it is worth being concrete about the hardware class this paper targets. TinyML devices are microcontrollers, digital signal processors, and dedicated neural-network accelerators that typically run between about 10 MHz and 250 MHz and can perform inference using under 50 mW of power; their memory budget is commonly two orders of magnitude smaller than a smartphone-class machine-learning device. This is not simply mobile-scale ML made smaller: it changes which models fit at all, how much slack exists for a benchmark harness itself, and how power can be measured in the first place.

Four properties of this hardware class make benchmarking it different from benchmarking a server or a phone. Power is the defining constraint, but it is also hard to measure fairly: devices vary enormously in the power they draw, and what counts as part of the measurement -- the data path, pre-processing, chip peripherals, firmware -- is not always obvious. Memory is limited enough that models built for standard ML benchmarks, which can need gigabytes, do not fit, and a benchmark harness with any real overhead risks not fitting either. Hardware is heterogeneous: alongside general-purpose microcontrollers sit non-standard accelerator architectures that may lack a standard system clock or debug interface a benchmark might otherwise assume, so existing performance benchmarks generally need re-engineering before they can even run. Software is heterogeneous too, since achieving the highest efficiency on a given chip often means a custom tool chain; a benchmark that restricts the inference stack too tightly would unfairly penalize solutions built on a different one.

Two more pieces of vocabulary matter before the suite's design can be described. Quantization -- reducing a model's numeric precision, typically to 8-bit integers, to save memory and compute -- can be applied in two ways: post-training quantization (PTQ) compresses an already-trained model without retraining it, while quantization-aware training (QAT) retrains the model with the lower precision simulated during training, usually recovering more accuracy at the cost of needing the original training pipeline. As Section 4 describes, MLPerf Tiny's two submission divisions are defined partly by which of these two a submitter may use. Separately, one of the four benchmarks scores its output with the area under the receiver-operating-characteristic curve (AUC), a threshold-free accuracy metric that fits naturally whenever, as in anomaly detection, the model produces a continuous score rather than a class label.
