## 5. Evaluation: The v0.5 Submission Round

Whether this design actually accommodates the field's diversity, rather than merely being built to, can only be tested by real submitters using it. MLPerf Tiny's first submission round, v0.5, closed in June 2021, and every submission was checked for compliance and transparently reviewed by the group of submitters together with a review committee before being published {C005}.

Table 2 summarizes what the round produced. It drew five submissions, split four to one between the closed and open divisions, and spanning five distinct combinations of numeric format, software framework, and hardware {C005}.

| Division | Changed vs. reference | Numerics | Framework | Hardware | Demonstrated advantage |
|---|---|---|---|---|---|
| Closed | none (fixed by rule) | INT-8 PTQ | TensorFlow Lite Micro | ARM microcontroller | Baseline performance on the reference platform |
| Closed | none (fixed by rule) | INT-8 PTQ | TensorFlow Lite Micro | RISC-V microcontroller | A RISC-V microcontroller customized for neural-network inference |
| Closed | none (fixed by rule) | FP-32 and INT-8 PTQ | LEIP Framework | Raspberry Pi 4 | A hardware-agnostic, software-only optimization toolchain |
| Closed | none (fixed by rule) | INT-8 PTQ | Syntiant TDK | Neural-network accelerator | Ultra-low-power hardware efficiency for deep neural networks |
| Open | training and model changed; dataset unchanged\* | INT-6/8 QAT | QKeras (training) / hls4ml (deployment) | FPGA | Rapid, end-to-end development of ML accelerators on reconfigurable hardware |

*Table 2. The five submissions to the v0.5 round (June 2021). \*Row 5's individual dataset/training/model marks did not survive text extraction from the source table intact; "dataset unchanged" is stated directly elsewhere in the source text, and "training and model changed" follows from this submission's use of quantization-aware training, which the closed-division rule (rows 1-4) prohibits. Source: project/paper.txt Table 2 and Section 6.2.*

Behind the one-line description in each row was a specific point in the deployment stack {C005}. One submitter used the round to show that its software development kit is hardware-agnostic and easy to use while preserving accuracy. A hardware vendor used it to show its neural-network accelerator's efficiency, which the authors attribute to a microarchitecture and datapath designed to avoid wait states. An academic research group used it to show the AI-compute capability of a microcontroller based on RISC-V, a free, open instruction-set architecture (Asanović and Patterson, 2014). A multi-disciplinary team used it to show hls4ml, an open-source workflow originally built for sub-microsecond inference at the Large Hadron Collider, repurposed here to compile a neural network onto an FPGA.

Three patterns held across all five submissions. INT-8 was the most common numeric format {C007}. Software frameworks ranged from an open-source interpreter to hardware-specific compilers, and measured power draw across the round's hardware spanned roughly microwatts to watts {C007}. A fourth pattern is notable for what did not happen: none of the five submissions modified the training dataset, even though a broader trend in machine learning has been moving toward data-centric development {C008}. Because this is a single round with five submissions, these patterns describe what this round's participants chose to do, not a demonstrated stable property of the field {L001}.

Read together, this range -- both divisions used, five different hardware categories, and a software-only entrant alongside four hardware-centric ones -- is consistent with the suite's modular, dual-division design achieving the goal it was built for {C006}. It let submitters at different layers of the deployment stack each show a distinct advantage, while the closed division's four entries remained directly comparable to one another and to the reference implementation {C006}. This answers the paper's research question affirmatively for the case actually tested. It does not establish that the pattern will hold in later rounds, that it would have failed under a non-modular alternative design, or that the closed division's current benchmarks, built mainly from fully-connected and convolutional layers, represent every architecture family a future TinyML benchmark might need {L001, L005}.
