# Verification of Gold Account — OPENHANDS

Verifier: independent check of `GOLD_ACCOUNT_DRAFT.md` and `gold_story.json` against the frozen snapshot only (`snapshot/paper.txt`, `snapshot/README__OpenHands__OpenHands.md`, `snapshot/README__OpenHands__benchmarks.md`). `PROJECT_ASSESSMENT.md` was read for context only. Line numbers (`L`) refer to `paper.txt` unless a README is named. Draft files were not modified.

## Verdict: **ACCEPT AFTER CORRECTIONS**

Most of the draft is accurate. Architecture, setup, and most numbers match the snapshot, and the README material is mostly kept apart from the paper. Two errors misattribute experiments: the GAIA 32.1% number and the GPQA "Table 7" source. The draft also scores readers on a research-gap claim that the legible paper text never makes, and it includes a scored nugget that is based only on a README. These must be fixed before the Gold Account can be used for scoring. The corrected versions are `gold_story.v1.json` and `GOLD_ACCOUNT_v1.md`.

## Judgement: is OPENHANDS still suitable given the repository divergence?

**Yes, suitable, with conditions.**

Reasons it remains suitable:
1. **The experiment scores reconstruction of the research, and the paper is self-contained.** The problem, architecture (§2, Fig. 2-3, App. F), agents (§3), evaluation setup (§4, Table 2), results (Tables 3-7), and limitations (App. A) all come from `paper.txt`. None of the v1 nuggets needs a README. After the Q12c removal, every nugget is answerable from the paper.
2. **The headline numbers are recoverable exactly.** Tables 4 (SWE-Bench Lite and HumanEvalFix rows), 5, 6, and 7 extract with consistent value counts. The only defect that cannot be recovered is Table 1's checkmark cells, and the v1 gold no longer depends on them.
3. **The divergence cannot corrupt the gold account, because the gold is paper-only.** The READMEs cannot contradict a research claim. They describe different, later artifacts: Agent Canvas, the software-agent-sdk, and the V1 benchmarks harness.

Conditions and caveats (these should be recorded with the experiment):
- **C1. The gold must stay paper-only.** Repo facts (Agent Canvas, the multi-repo split, the V1 benchmarks) must not be scored as research content. If the experiment wants to test source separation, that needs a separate, explicitly labeled artifact rubric, not a Q12 nugget.
- **C2. Risk from input contamination.** If the system under test (for example, a writing skill) is given the current READMEs as project material, it may describe "Agent Canvas", "ACP agents", or a "software-agent-sdk" as the paper's system. Under the paper-authority rule, that is a factual error and should be penalized. This makes OPENHANDS a harder test than a project whose repository matches its paper. Report it separately so it is not confused with general reconstruction accuracy.
- **C3. Reproducibility cannot be assessed from the snapshot.** Neither current repository contains the paper-era code (AgentHub, the CodeActAgent v1.5/v1.8 prompts, or V0 evaluation scripts). The benchmarks README only links to "benchmarks from OpenHands V0". Claims about artifact availability or reproducibility must not be scored. The experiment measures communication fidelity, not reproducibility, so this does not disqualify the project.
- **C4. The results are tied to their time.** They use mid-2024 models (gpt-4o-2024-05-13, claude-3-5-sonnet-20240620). Readers must report them as the paper's numbers, not as current OpenHands performance.

The project would be **unsuitable** if the evaluation required readers or writers to ground claims in a code artifact that matches the paper. The snapshot has no such artifact.
